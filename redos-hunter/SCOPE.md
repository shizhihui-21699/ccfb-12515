# 支持的正则语法边界（SCOPE）

本工具静态分析的目标是**回溯型正则引擎**（PCRE / JavaScript `RegExp` / Python `re` / Java
`java.util.regex` / .NET 等）下的灾难性回溯（ReDoS）。Go 标准库 `regexp` 基于 RE2、线性时间，
本身不会回溯爆炸，因此只作为**安全改写目标**和对照引擎，不作为被测漏洞引擎。

## 1. 支持完整静态分析的语法（Tier 1）

以下语法可解析、建 NFA、做歧义/重叠分析、生成攻击串并实测：

| 类别 | 语法 |
|---|---|
| 字面量 | 普通字符、转义字面量 `\.` `\(` `\\` 等 |
| 字符类 | `[abc]` `[a-z]` `[^...]`、嵌套 `[]]`、类内转义 |
| 预置类 | `\d \D \w \W \s \S`（ASCII 语义）、`.`（受 `s` 标志影响） |
| 通用转义 | `\n \r \t \f \v \0`、`\xHH`、`\uHHHH`、`\u{HHHH}`、`\cJ`、八进制 `\012` |
| 量词 | `*` `+` `?`、`{n}` `{n,}` `{n,m}`，贪婪与懒惰（`*?` `+?` `??` `{n,m}?`） |
| 分组 | 捕获 `(...)`、非捕获 `(?:...)`、命名组 `(?<n>...)` / `(?P<n>...)` |
| 分支 | `a|b|c` |
| 锚点/断言 | `^` `$`、`\b` `\B`（多行使 `^/$` 语义变化仅影响攻击串构造，不影响 NFA 判定） |
| 行内标志 | `i`（ASCII 大小写折叠）、`m`、`s`（dotall）；以及 JS/Python 风格 `(?i:...)` `(?i)` |
| 环视（有限支持） | `(?=...)` `(?!...)` `(?<=...)` `(?<!...)`：**可解析可匹配**，其内部模式单独做 ReDoS 分析；环视与外层之间的交互标注为降级结论 |

## 2. 可解析但不纳入 NFA 主分析的语法（Tier 2，结果显式标注 `degraded`）

- 反向引用 `\1`、`\k<name>`、`(?P=n>)`：非正则语言，无法用 NFA 精确建模。匹配器支持实测，
  但静态结论降级为"仅经验证据"。
- 原子组 `(?>...)`、占有量词 `*+ ` `++`：**天然免疫回溯**，遇到时把该子树标记为回溯屏障，
  屏障内部不产生漏洞结论，屏障外部正常分析。
- Unicode 属性 `\p{L}` `\P{...}`、字素簇 `\X`、POSIX 类 `[:digit:]`、Java 类交集 `[a&&[^b]]`：
  解析为不透明字符类，按"可能匹配多字符"保守处理，可能产生误报，置信度标低。
- 递归 `(?R)` `(?1)`、条件 `(?(1)...)`、平衡组 `(?<>)`：无法静态判定，跳过并在告警中列出。

## 3. 源码抽取支持的语言

| 语言 | 抽取对象 |
|---|---|
| JavaScript / TypeScript（含 JSX/TSX） | 正则字面量 `/pat/flags`（含类内 `/`、转义）；`new RegExp("...", "...")` 字符串实参 |
| Python | `re.compile / re.match / re.search / re.fullmatch / re.sub / re.subn / re.findall / re.finditer / re.split` 的 pattern 实参；普通/raw/bytes/三引号字符串与相邻拼接 |
| Go | `regexp.Compile / MustCompile / CompilePOSIX / MustCompilePOSIX` 的字符串/原始字符串实参 |
| Java | `Pattern.compile(...)` 实参 |
| 通用兜底 | 任意语言中形似正则、传入名为 `compile/match/regex/...` 的函数的字符串字面量（标注 `heuristic`，低置信度） |

## 4. 明确不做的事

- 不分析运行时动态拼接出的正则（只分析源码中可静态确定的字面量；拼接含变量时标注不可解析）。
- 不保证零误报：所有静态结论都必须经过沙箱实测佐证，前端同时展示静态等级与经验等级。
- 不做代码自动重写（只给改写建议 + 等价性反例检查，改动由人决定）。
