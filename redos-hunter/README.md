# redos-hunter

静态检测代码库中正则表达式的**灾难性回溯（ReDoS）**，并给出可复现的实测证据与安全等价改写。

- **分析引擎**：Go，零第三方依赖（仅标准库）。
- **结果页**：Svelte 5 + Vite + TypeScript，主题感知，可加载任意扫描报告。
- **实测佐证**：内置精确模拟 Perl/PCRE/JS 语义的回溯 VM（步数与机器无关），并可外连本机
  Node.js / Python 真实引擎交叉验证。

## 它解决什么问题

一条写得不好的正则（如 `(a+)+$`）在特制输入下回溯次数指数增长，能把接口线程卡死。
本工具把检测拆成相互印证的三层：

1. **静态判定** —— 解析正则、建 Thompson ε-NFA，用配对自动机（pair automaton）识别指数级歧义泵，
   再辅以量词重叠结构规则识别多项式级回溯；
2. **攻击构造 + 沙箱实测** —— 自动生成 `pump^n + killer` 攻击串，在回溯 VM 上测 n=1..N 的步数曲线，
   拟合出指数/多项式/线性增长，撞步数上限即"会卡死"的工程信号；
3. **安全改写** —— 基于 AST 渲染给出原子组、嵌套量词合并等改写，并用有限样本做等价性反例检验。


## 构建与使用

```bash
# 1. 构建 CLI
go build -o redos-hunter ./cmd/redos-hunter

# 2. 扫描代码库，产出 JSON 报告
./redos-hunter scan ./src --out report.json --max-n 24

# 3. 结果页
cd web
npm install
npm run dev          # 打开 http://localhost:5173，默认加载样例报告
# 或把自己的 report.json 通过页面右上角「加载报告」打开
```

CLI 选项：

| 选项 | 默认 | 含义 |
|---|---|---|
| `--step-cap N` | 2000000 | 回溯 VM 步数上限，撞到即判定可卡死 |
| `--max-n N` | 26 | 攻击串 pump 重复次数上界 |
| `--no-external` | 关 | 不调用 Node/Python 真实引擎 |
| `--external-timeout D` | 3s | 外部引擎单次超时（超时本身即卡死证据） |
| `--samples N` | 200 | 改写等价性检验的样本数 |

## 判定原理（简述）

- **指数级**：NFA 上同一输入若存在两条不同接受路径，回溯引擎就要枚举它们。配对自动机同时模拟
  两条路径（强制走**不同的边**），一旦经非空串回到某个对角状态 `(s,s)`，该串就是 pump，
  其 k 次重复产生 ≥2^k 条路径。对"量词套量词"这类丢失迭代身份的结构，另用 AST 规则
  （嵌套量词字符集相交、重叠分支等）补齐。
- **多项式级**：≥2 层在重叠字符集上、且中间无明确分隔字面量的量词，失败输入下产生 O(n^k) 回溯。
  单层量词与后继字面量重叠仅线性，不计为 ReDoS（控制误报）。
- **免疫结构**：原子组 `(?>...)` 与占有量词 `*+ / ++` 是回溯屏障，其内部不出漏洞结论。

实测曲线用对数坐标展示：指数模式 n 每 +2 步数约 ×4，二次模式 n 翻倍步数约 ×4，线性模式近似等比。

## 支持的语法

完整可分析（Tier1）：字面量、字符类、`\d \w \s` 及其反类、`.`、四种量词（贪婪/懒惰/占有）、
捕获/非捕获/命名组、分支、`^ $ \b \B`、行内 `i m s` 标志、环视（内部单独分析）。

可解析但降级（Tier2，报告显式标注）：反向引用、原子组/占有量词（作为屏障）、Unicode 属性
`\p{}`、递归/条件分组（跳过并告警）。详见 [SCOPE.md](SCOPE.md)。

源码抽取支持 JavaScript/TypeScript（正则字面量 + `new RegExp`）、Python（`re.*` 实参，
含 raw/bytes/三引号/相邻拼接）、Go（`regexp.*`）、Java（`Pattern.*`），以及任意语言的
低置信度启发式兜底。

## 边界与诚实说明

- 只分析**源码中可静态确定**的字面量；运行时动态拼接的正则不分析（会标注不可解析）。
- 静态结论不追求零误报，因此每条漏洞都必须经回溯 VM 实测佐证，前端同时展示静态等级与经验等级。
- 等价性检验是有限样本反例搜索，**不是形式化证明**；改写默认不自动改代码，由人确认。
- Go 标准库 `regexp`（RE2）本身线性不回溯，只作为安全改写目标与对照，不作为被测漏洞引擎。
